## Existing capabilities and gaps

| Area | Findings before this milestone |
|---|---|
| Core | Real registry, schema checks, permissions, SQLite plan/execution history, rule/LLM planning and argument revision. No output binding between steps. Exhausted postconditions could still lead to COMPLETE when ToolResult.success was true. |
| Documents/vision | Real document renderers and structured image/PDF extraction, but no source-aware authoring or assignment-solving layer. Extraction already uses a section/table shape compatible with rendering. Existing DOCX reading/editing is absent. |
| Finance | Deterministic integer-money/database service and registry tools already integrated. Agent summary discarded tool-provided answers. Budget-report service exists but has no query tool; largest-expense intent is not implemented by the current parser. |
| Processes | Real allowlisted subprocess invocation with captured diagnostics. Nonzero exit was still a successful tool invocation, without an agent-level exit check. Timeout byte output handling was unsafe. No device/capability runtime discovery layer. |
| Computer/browser | Real Fedora/X11 and Playwright adapters behind protocols. NullComputerAgent honestly reports unavailable. Computer methods are not a semantic observe/correct worker; no Windows/Phone implementation or capability router. Browser actions return observations. |
| Scheduler | Already invokes the full agent loop through the CLI callback. Returned failed/blocked runs were incorrectly marked succeeded. Stored offset-aware job times could conflict with naive interval arithmetic. |
| Future systems | Education/NeoColab connector, adaptive code-edit/build/replan loop, multi-device routing, and assignment content authoring remain unimplemented. Existing protocol methods and deliberate unavailable backends are not fake working capabilities. |

The roadmap correctly identified assignment workflows as a next goal, but a reliable result-passing
and verification foundation was missing underneath it. The chosen change extends existing plans
and execution instead of replacing subsystems or adding a second engine.

## Implemented milestone

Backward typed references; static plan and runtime argument validation; failure on unmet
postconditions; artifact existence and process exit verification; conservative replay boundaries;
per-attempt evidence; actual output paths and deterministic messages; scheduler state propagation
and repeat-tick timestamps; CLI UTF-8 output and portable real-Python tests. No project dependencies
were added. See `WORKFLOWS.md` for executable plan examples and limitations.

## Limits and next milestone

This is sequential workflow infrastructure, not the complete autonomous-agent vision. Copying a
source into a report and preserving extracted tables now works through the general engine; answering
new questions from those sources still needs a provider-backed authoring step. Next: source-aware
content generation with provenance and explicit unresolved tasks, native DOCX structure reading,
then adaptive replanning for tested code/assignment work. Keep submission permission-gated.

Artifact existence checks do not prove content or layout correctness. Process execution retains the
documented lack of OS-level isolation. Failed third-party tools may have partial side effects;
there is no rollback/exactly-once guarantee. Successful calls that fail verification stop rather than
being replayed automatically.
